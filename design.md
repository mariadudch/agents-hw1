# Design: add-weekly-study-tracker

## Context
Статическое приложение без сборки и зависимостей. Открывается из файла или через простой локальный сервер (для варианта B с ES-модулями).

## Data Model
- `Task = { id: string, title: string, hours: number, done: boolean }`
- Состояние: `{ tasks: Task[], filter: 'all' | 'active' }`
- `id` генерируется локально (счётчик или `Date.now()` с суффиксом), уникальность в пределах списка.
- Стартовые данные — константа `SEED` из трёх задач (8 ч, из них 2 ч done).

## Domain Functions (в B — `domain.mjs`, в A — блок внутри скрипта)
Чистые функции без DOM:
- `addTask(tasks, {title, hours})` → новый массив
- `removeTask(tasks, id)` → новый массив
- `toggleDone(tasks, id)` → новый массив
- `validate({titleRaw, hoursRaw})` → `{ ok, errors: { title?, hours? }, value? }`
- `totals(tasks)` → `{ totalHours, doneHours, progress }`
- `visible(tasks, filter)` → массив для отображения

## Calculations
- `totalHours = Σ hours` по всем задачам
- `doneHours = Σ hours` по задачам с `done = true`
- `progress =ы totalHours === 0 ? 0 : Math.round(100 * doneHours / totalHours)`
- `totals` всегда получает полный `tasks`, никогда не результат `visible`
- Контрольные значения:
  - старт: 2/8 → 25
  - отметка «Практики»: 6/8 → 75
  - удаление «Практики»: 2/4 → 50
  - добавление «Тест» 0,5 ч: 2/8,5 → 24 (23,53 округляется вниз)
  - добавление «Тест» 24 ч: 2/32 → 6 (6,25 округляется вниз)
  - пустой список → 0

## Validation Rules
- Название: `titleRaw.trim().length > 0`
- Часы: сначала проверка на пустую строку (ошибка «Укажите часы»), затем замена запятой на точку, `Number()`, проверки `Number.isFinite`, `0.5 ≤ h ≤ 24`, `h * 2` целое
- При ошибке поля формы не очищаются. Очистка только после успешного добавления
- Ошибки выводятся в элементах рядом с полями, связанных через `aria-describedby`

## UI
- Форма: поле «Название», поле «Часы» (`inputmode="decimal"`), кнопка «Добавить», у каждого `label`
- Фильтр: «Все» / «Активные»
- Элемент списка: чекбокс с подписью «Готово», название, часы, кнопка «Удалить» с доступным именем, включающим название задачи
- Итоги: «Всего N ч · выполнено M ч · P%»
- CSS: `box-sizing: border-box`, `max-width: 100%`, перенос длинных слов, без фиксированной ширины больше 390 px

## Rendering
Однонаправленный поток: действие → новая версия `tasks` → `render()` перерисовывает список и итоги.

## Persistence (необязательное)
- Ключ, например `tracker-v2.tasks`; чтение и запись в `try/catch`
- Ошибка или невалидный JSON → работа в памяти со `SEED` и видимое сообщение «Сохранение недоступно, данные живут до закрытия страницы»

## Variant Mapping
- **A:** `tracker-v2.html` с `<style>` и `<script>` внутри
- **B:** `domain.mjs` (чистая логика), `app.mjs` (DOM и события, импортирует domain), `styles.css`, `index.html`, `tests/acceptance.test.mjs` (тестирует domain через `node:test` и `node:assert`, без внешних пакетов)

## Risks
- **`file://` и ES-модули в B:** часть браузеров блокирует загрузку модулей из файла. Нужен локальный сервер или явное указание в инструкции.
- **`file://` и localStorage:** при открытии через `file://` поведение localStorage зависит от браузера и его настроек. Хранилище может быть недоступно (исключение при обращении), может не сохраняться между сеансами или может быть общим для разных локальных файлов. Тогда данные трекера могут перемешаться с данными другой страницы под тем же ключом. Меры:
  - любые обращения к хранилищу в `try/catch`, при сбое работа в памяти и сообщение пользователю;
  - ключ с префиксом приложения, чтобы снизить риск пересечения;
  - невалидные или чужие данные под ключом не ломают приложение (откат к `SEED`);
  - сохранение между сеансами при `file://` не гарантируется. Для надёжной проверки открывать через локальный сервер.
- **Дробные часы:** шаг 0,5 точно представим во float, погрешности суммирования не ожидаются.
