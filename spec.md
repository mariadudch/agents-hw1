# Spec delta: tracker

## ADDED Requirements

### Requirement: Модель задачи и стартовые данные
Каждая задача MUST иметь поля `id` (уникальный), `title` (строка), `hours` (число), `done` (boolean). При первом запуске (или если сохранённых данных нет) приложение MUST загрузить стартовый пример: «Чтение» 2 ч done=true, «Практика» 4 ч done=false, «Повторение» 2 ч done=false.

#### Scenario: Стартовые итоги
- WHEN приложение открыто со стартовым примером
- THEN всего 8 ч, выполнено 2 ч, прогресс 25%

### Requirement: Операции меняют данные
Добавление, удаление и переключение `done` MUST менять массив задач, а не только DOM. Итоги и прогресс MUST пересчитываться после каждой операции. После успешного добавления форма MUST очищаться.

#### Scenario: Добавление задачи на 0,5 ч
- WHEN на стартовом примере добавлена задача «Тест» на 0,5 ч
- THEN задача добавлена с done=false, всего 8,5 ч, выполнено 2 ч, прогресс 24%, форма очищена

#### Scenario: Добавление задачи на 24 ч
- WHEN на стартовом примере добавлена задача «Тест» на 24 ч
- THEN задача добавлена с done=false, всего 32 ч, выполнено 2 ч, прогресс 6%, форма очищена

#### Scenario: Удаление одной задачи
- WHEN на стартовом примере удалена «Практика»
- THEN всего 4 ч, выполнено 2 ч, прогресс 50%

#### Scenario: Отметка «Практики»
- WHEN «Практика» отмечена готовой на стартовом примере
- THEN выполнено 6 ч из 8 ч, прогресс 75%

#### Scenario: Удаление всех задач
- WHEN все задачи удалены
- THEN итог 0 ч и прогресс 0%, на экране нет NaN и Infinity

### Requirement: Валидация ввода
Название MUST быть непустым после trim. Часы MUST быть числом в диапазоне 0,5–24 с шагом 0,5. Пустое значение часов MUST считаться ошибкой и MUST NOT приравниваться к 0. При ошибке задача MUST NOT добавляться, сообщение MUST показываться рядом с соответствующим полем, введённые значения формы MUST сохраняться.

#### Scenario: Пустое название
- WHEN название пустое или состоит из одних пробелов
- THEN задача не добавляется, рядом с полем названия видна ошибка, введённые часы сохранены

#### Scenario: Пустые часы
- WHEN поле часов пустое
- THEN задача не добавляется, рядом с полем часов видна ошибка

#### Scenario: Отрицательные часы
- WHEN введены отрицательные часы
- THEN задача не добавляется, рядом с полем часов видна ошибка, название сохранено

#### Scenario: Часы вне шага или диапазона
- WHEN введено 0, 0,3, 1,25 или 24,5
- THEN задача не добавляется и видна ошибка

### Requirement: Расчёт прогресса
Прогресс MUST вычисляться как округление(100 × сумма часов done / сумма часов всех задач). Если задач нет (сумма 0), прогресс MUST быть 0%.

#### Scenario: Пустой список
- WHEN задач нет
- THEN прогресс 0%

### Requirement: Фильтр видимого списка
Фильтр MUST влиять только на видимый список. Итоговые часы и прогресс MUST считаться по всем задачам.

#### Scenario: Фильтр «активные»
- WHEN на стартовом примере включён фильтр «активные»
- THEN в списке видны только «Практика» и «Повторение», прогресс остаётся 25%, итог 8 ч

### Requirement: Доступность и адаптивность
Интерфейс MUST читаться на ширине 390 px без горизонтального скролла. Каждое поле и каждая кнопка MUST иметь подпись (видимый `label` или доступное имя).

#### Scenario: Узкий экран
- WHEN ширина окна 390 px
- THEN горизонтального скролла нет, текст и элементы управления читаемы

### Requirement: Сохранение в localStorage (необязательное)
Если улучшение реализовано, задачи SHOULD сохраняться в localStorage. Если хранилище недоступно, приложение MUST показать понятное сообщение и продолжить работу в памяти.

#### Scenario: Хранилище недоступно
- WHEN localStorage бросает исключение при чтении или записи
- THEN показано сообщение о работе без сохранения, операции с задачами работают
